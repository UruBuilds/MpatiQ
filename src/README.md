#  `src/` — The Soul of MpatiQ

Welcome to the root of MpatiQ’s living system.  
Everything here is built with intention and layered with care. This isn’t a scattered file system. It’s a composition—each part tuned to its role.

## 📂 Directory Harmony

### `components/`

Small, reusable visual elements.  
Buttons. Modals. Cards. Always modular.  
If you can carry it in your hand, it lives here.

### `screens/`

Large visual structures—full page flows or views.  
These represent **moments** in the user journey.  
Each file here holds an entire experience (e.g., `TrustSetup.jsx`, `UserHome.jsx`).

### `layouts/`

Page skeletons.  
Wrap content in shared structure (e.g., navbars, sidebars, headers).  
One level above screens. One level beneath pages.

### `styles/`

Design tokens, utility classes, and CSS extensions.  
If `components` are words and `screens` are paragraphs, this is the grammar.

### `hooks/`

Custom React hooks.  
Extract logic like memory, scroll, auth state, etc.  
Use these to keep components pure and declarative.

### `context/`

Shared state containers (e.g., Theme, Auth, Trust).  
React Contexts that span the app, rooted in empathy and clarity.

### `core/`

MpatiQ’s system primitives.  
Not UI. Not visual. These are the **engines**—trust score calculators, signal clarity models, habit recognition algorithms.  
This is the cathedral beneath the surface.

### `utils/`

Tiny helpers. Project-specific.  
Used when logic is too small for `core/` but too repeatable to inline.

### `assets/`

Images, logos, svgs, and any static visual content.

---

##  Philosophy

This directory is structured to be:

- **Intuitive to navigate**
- **Emotionally grounded**
- **Technically scalable**

We’re building trust, after all.  
It should show in our folders.
